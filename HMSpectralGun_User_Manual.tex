\section{Purpose and Scope}

\code{HMSpectralGun} generates synthetic stellar spectra using Turbospectrum. This manual covers the production workflow for synthetic spectra with the two production entry points currently documented for routine use:

\begin{longtable}{p{0.34\textwidth}p{0.56\textwidth}}
\toprule
\textbf{Entry point} & \textbf{Purpose} \\
\midrule
\code{main.py} & Serial production. It reads an \code{input.ts} file and synthesizes the requested spectra one after another. \\
\code{main\_parallel.py} & Parallel production. It follows the same synthesis logic, but distributes independent spectra across multiple worker processes. \\
\bottomrule
\end{longtable}

\begin{importantbox}
This manual is limited to synthetic-spectrum production. Line-by-line abundance fitting is not part of the production manual scope. If a line-fit configuration is present in the repository, treat it as a separate analysis workflow and adapt its placeholder paths to the local dataset before use.
\end{importantbox}

\section{Quick Start}

From a fresh clone, create a Python environment, install the required packages, export the runtime paths for Turbospectrum, and run a small validation job.

\begin{lstlisting}[language=bash]
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
\end{lstlisting}

Export the minimum runtime paths:

\begin{lstlisting}[language=bash]
export HMSPECTRALGUN_EXEC_PATH="/path/to/turbospectrum/exec-gf"
export HMSPECTRALGUN_LAUNCH_PATH="/path/to/turbospectrum/COM/santerre"
\end{lstlisting}

Prepare \code{input.ts} and run the serial workflow:

\begin{lstlisting}[language=bash]
python main.py --input input.ts --progress
\end{lstlisting}

For a parallel batch:

\begin{lstlisting}[language=bash]
python main_parallel.py --input input.ts
\end{lstlisting}

\begin{notebox}
The recommended first run is a single-spectrum test. Do not start a large batch until one spectrum has been generated, inspected, and matched to the expected wavelength range, resolution, abundance pattern, and output naming convention.
\end{notebox}

\section{Requirements}

\subsection{Python environment}

Python 3.10 or newer is recommended. The production scripts use the following Python packages:

\begin{itemize}
  \item \code{numpy}, \code{pandas}, \code{tqdm}, and \code{mendeleev};
  \item \code{scipy}, for resampling and numerical utilities;
  \item \code{PyAstronomy}, for instrumental convolution;
  \item \code{matplotlib}, when plotting or report utilities are available in the local workflow.
\end{itemize}

A minimal import check is:

\begin{lstlisting}[language=bash]
python -c "import numpy, pandas, scipy, matplotlib; print('core stack: ok')"
python -c "import mendeleev, PyAstronomy; print('spectral stack: ok')"
\end{lstlisting}

\subsection{Turbospectrum runtime}

Turbospectrum must be compiled and reachable through environment variables. The recommended variables are:

\begin{longtable}{p{0.38\textwidth}p{0.52\textwidth}}
\toprule
\textbf{Variable} & \textbf{Meaning} \\
\midrule
\code{HMSPECTRALGUN\_EXEC\_PATH} & Directory containing the Turbospectrum executables, typically including \code{babsma\_lu} and \code{bsyn\_lu}. \\
\code{HMSPECTRALGUN\_LAUNCH\_PATH} & Directory where generated \code{.com} scripts are written and executed. \\
\bottomrule
\end{longtable}

Optional overrides are available for non-standard installations:

\begin{longtable}{p{0.40\textwidth}p{0.50\textwidth}}
\toprule
\textbf{Variable} & \textbf{Default or use case} \\
\midrule
\code{HMSPECTRALGUN\_DATASET\_MODEL\_PATH} & MARCS model dataset path. Default: \code{./marcs\_generator/dataset}. \\
\code{HMSPECTRALGUN\_CONTOPAC\_PATH} & Continuum opacity path. Default: \code{\$\{HMSPECTRALGUN\_LAUNCH\_PATH\}/contopac}. \\
\code{HMSPECTRALGUN\_INTERPOLATOR\_EXE} & MARCS interpolation executable. Default: \code{./marcs\_generator/interpol\_modeles}. \\
\code{HMSPECTRALGUN\_BABSMA} & Explicit path to \code{babsma\_lu}, if a directory-level executable path is not sufficient. \\
\code{HMSPECTRALGUN\_BSYN} & Explicit path to \code{bsyn\_lu}, if a directory-level executable path is not sufficient. \\
\bottomrule
\end{longtable}

\begin{importantbox}
On Linux, the generated Turbospectrum \code{.com} scripts use \code{csh} with the shebang \code{\#!/bin/csh -f}. Install \code{csh} or \code{tcsh} before running production jobs on systems where it is not already available.
\end{importantbox}

\section{Main Input File: \code{input.ts}}

The serial and parallel workflows are driven by an \code{input.ts} file. The parser expects six header lines followed by a spectral-production table.

\subsection{Required structure}

\begin{enumerate}
  \item \code{savepath}: output directory for generated spectra;
  \item \code{linelistpath}: directory containing line-list files and line-list index files;
  \item \code{modelpath}: directory containing atmosphere models or model products;
  \item \code{ExplicitModel=True|False};
  \item \code{interp=True|False|nearest};
  \item third keyword, read by the parser as \code{NLTE};
  \item spectral-production table with either 15 or 17 columns.
\end{enumerate}

Minimal example:

\begin{lstlisting}
/path/output_spectra/
/path/linelists/
/path/models/
ExplicitModel=False
interp=True
NLTE=False
3600,1.0  -1.00  0.20  15000  15500  2.0  st  *  28000  0.02  *  linelistH.ts  abu.ts  *  txt
\end{lstlisting}

\subsection{Table columns}

\begin{longtable}{p{0.07\textwidth}p{0.24\textwidth}p{0.59\textwidth}}
\toprule
\textbf{No.} & \textbf{Column} & \textbf{Meaning} \\
\midrule
1 & \code{Model} & Explicit model filename, or compact atmospheric identifier \code{Teff,logg}. \\
2 & \code{[Fe/H]} & Metallicity. \\
3 & \code{[a/Fe]} & Alpha-enhancement parameter. \\
4 & \code{lam\_i} & Initial wavelength. \\
5 & \code{lam\_f} & Final wavelength. \\
6 & \code{xi} & Microturbulence. \\
7 & \code{chemistry} & Chemistry mode: \code{st}, \code{ap}, \code{ae}, \code{mc}, or \code{hc}. \\
8 & \code{sampl} & Resampling step, or \code{*} to skip resampling. \\
9 & \code{RES} & Resolving power for instrumental convolution. \\
10 & \code{resnum} & Numerical synthesis step used by Turbospectrum. \\
11 & \code{monoelem} & \code{*}, an atomic species such as \code{FeI}, or a molecule such as \code{CO}, \code{OH}, or \code{CN}. \\
12 & \code{linelist\_file} & Index file listing the line-list files to use. \\
13 & \code{abu\_file} & Abundance file. \\
14 & \code{snr} & Signal-to-noise value for noise injection, or \code{*}. \\
15 & \code{extension} & Output extension, for example \code{txt}. \\
16 & \code{override\_elem} & Optional atomic number for direct abundance override. \\
17 & \code{override\_xfe} & Optional forced \code{[X/Fe]} value. \\
\bottomrule
\end{longtable}

\begin{importantbox}
If columns 16 and 17 are present, the explicit abundance override has maximum priority over the abundance value read from \code{abu\_file}.
\end{importantbox}

\section{Auxiliary Input Files}

\subsection{Abundance file}

The abundance file, for example \code{abu.ts}, is a two-column text file:

\begin{itemize}
  \item column 1: atomic number;
  \item column 2: abundance offset \code{[X/Fe]}.
\end{itemize}

Example:

\begin{lstlisting}
8 0.20
12 0.20
26 0.00
612613 15.0
\end{lstlisting}

The special identifier \code{612613} is interpreted as the carbon isotopic ratio \code{C12/C13}.

\subsection{Line-list index file}

The value given in \code{linelist\_file} is an index file containing one line-list filename per line:

\begin{lstlisting}
vald_1.lin
vald_2.lin
\end{lstlisting}

Files are resolved relative to \code{linelistpath} for the production workflow.

\section{Serial Production Workflow}

The serial workflow is the safest option for validation, debugging, and small jobs.

\begin{lstlisting}[language=bash]
python main.py --input input.ts
\end{lstlisting}

With a progress bar:

\begin{lstlisting}[language=bash]
python main.py --input input.ts --progress
\end{lstlisting}

The workflow performs the following operations:

\begin{enumerate}
  \item reads and validates the production rows from \code{input.ts};
  \item selects, prepares, or interpolates the atmospheric model according to \code{ExplicitModel} and \code{interp};
  \item writes the Turbospectrum \code{.com} script into the launch directory;
  \item runs Turbospectrum;
  \item creates a descriptive header in the output spectrum;
  \item optionally applies instrumental convolution using \code{RES};
  \item optionally applies resampling using \code{sampl};
  \item optionally injects noise using \code{snr}.
\end{enumerate}

\section{Parallel Production Workflow}

The parallel workflow is intended for batch production after the serial validation run has succeeded.

\begin{lstlisting}[language=bash]
python main_parallel.py --input input.ts
\end{lstlisting}

Main characteristics:

\begin{itemize}
  \item uses multiple processes, typically up to \code{cpu\_count() - 1};
  \item writes a main log named \code{synth\_main\_YYYYMMDD\_HHMMSS.log};
  \item creates dedicated worker logs;
  \item renames final outputs with a suffix such as \code{\_k<index>} to avoid collisions between workers.
\end{itemize}

Use the parallel workflow when the input file contains many independent spectra, the machine has enough CPU cores, and the serial workflow has already validated the configuration.

\section{Optional Shell Commands from Anywhere}

To launch the production workflows without manually moving into the repository directory, define shell helper functions.

For \code{zsh}, add the following block to \code{\textasciitilde/.zshrc}. For \code{bash}, add the same block to \code{\textasciitilde/.bashrc}.

\begin{lstlisting}[language=bash]
spectralgun() {
  /path/to/HMSpectralGun/.venv/bin/python /path/to/HMSpectralGun/main.py --input "${1:-input.ts}" --progress
}

parallel_spectralgun() {
  /path/to/HMSpectralGun/.venv/bin/python /path/to/HMSpectralGun/main_parallel.py --input "${1:-input.ts}"
}
\end{lstlisting}

Reload the shell configuration:

\begin{lstlisting}[language=bash]
source ~/.zshrc
# or, if using bash:
source ~/.bashrc
\end{lstlisting}

Usage:

\begin{lstlisting}[language=bash]
spectralgun /path/to/input.ts
parallel_spectralgun /path/to/input.ts
\end{lstlisting}

\section{Generated Outputs and Naming}

The production scripts generate Turbospectrum launch files, synthetic spectra, logs, and optional post-processed products.

\begin{longtable}{p{0.34\textwidth}p{0.56\textwidth}}
\toprule
\textbf{Product} & \textbf{Location or convention} \\
\midrule
Turbospectrum scripts & \code{<name>.com} files written in \code{HMSPECTRALGUN\_LAUNCH\_PATH}. \\
Synthetic spectra & Written to \code{savepath}. \\
Convolved spectra & Typically include a resolution tag such as \code{\_RXXk}. \\
Noise-injected spectra & Typically include a tag such as \code{\_SNR<value>}. \\
Abundance-overridden spectra & Include an abundance tag such as \code{\_Fep010}. \\
Parallel main log & \code{synth\_main\_YYYYMMDD\_HHMMSS.log}. \\
Worker logs & Dedicated log files generated by the parallel workflow. \\
\bottomrule
\end{longtable}

\section{Troubleshooting}

\begin{longtable}{p{0.38\textwidth}p{0.52\textwidth}}
\toprule
\textbf{Symptom} & \textbf{Likely cause and action} \\
\midrule
\code{ModuleNotFoundError} & A Python dependency is missing or the wrong environment is active. Activate the intended environment and install the missing package. \\
\code{No safe interpolation pair} & The MARCS grid does not contain a safe interpolation pair for the requested parameters. Check the model dataset coverage. \\
\code{No complete safe MARCS interpolation cube} & The local model dataset is incomplete for the requested interpolation. Expand or correct the MARCS grid. \\
\code{Missing/empty spectrum output} & Turbospectrum did not produce a valid spectrum. Inspect the generated \code{.com} file and logs in the launch directory. \\
\code{Spectrum already exists} & A non-empty output already exists. The run was skipped intentionally to avoid overwriting existing products. \\
\bottomrule
\end{longtable}

\section{Pre-Batch Checklist}

\begin{checklistbox}
Before launching a long batch, verify the following points:
\begin{itemize}
  \item the Python environment is active and all required imports succeed;
  \item \code{HMSPECTRALGUN\_EXEC\_PATH} points to the Turbospectrum executable directory;
  \item \code{HMSPECTRALGUN\_LAUNCH\_PATH} exists and is writable;
  \item \code{savepath}, \code{modelpath}, and \code{linelistpath} exist and are readable or writable as needed;
  \item \code{input.ts} has been tested on one spectrum;
  \item all line-list index files resolve to existing line lists;
  \item all \code{abu\_file} entries are present and correctly formatted;
  \item \code{csh} or \code{tcsh} is installed on Linux systems;
  \item existing output files have been intentionally kept, moved, or removed before rerunning.
\end{itemize}
\end{checklistbox}
